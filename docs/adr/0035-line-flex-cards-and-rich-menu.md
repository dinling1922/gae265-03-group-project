# LINE bot 的 Flex 卡片與圖文選單：版面在轉接層、資料仍只來自 MCP

[ADR-0033](0033-line-bot-adapter-over-mcp.md) 的第一版只回純文字加快速回覆。實機測試後要優化體驗：回覆改成 Flex 卡片，並加上聊天室底部常駐的圖文選單（Rich Menu）。這份記下範圍、按鈕動作與資料來源，不改變「資料只有一個出口：MCP」的原則。

## 決定

- **兩階段**：階段 1 是 Flex 卡片（說明、比較列表與詳情、待辦）；階段 2 是圖文選單。圖文選單需要設計者提供選單圖，階段 2 不阻擋階段 1 上線。
- **卡片全部指令都改**，綁定相關訊息（成功、失敗、限額、解除）維持純文字，內容簡單、不值得做卡。每則 Flex 都帶 `altText`（通知與舊版 LINE 顯示），內容用既有的純文字摘要。Flex 組裝失敗、超過 LINE 上限（單則 JSON 50 KB、輪播最多 12 張、一次回覆最多 5 則）或 LINE 拒絕時，**降級回既有的純文字回覆**，不讓使用者沒回應。
- **卡片按鈕用 postback，不用傳文字**：聊天室不會多出「比較 1」這類使用者沒打的字。postback 的資料只放指令與識別碼，不放個資。轉接層新增處理 `postback` 事件，沿用既有的事件 id 去重，並與純文字指令走**同一個指令處理器**，所以打字（「比較」「待辦」）一樣有效。
- **卡片上的比較按鈕帶比較紀錄 id，不帶列表編號**：卡片在較早的訊息裡，使用者可能隔很久才按，列表順序早就變了；帶 id 才不會點到錯的。MCP 的 `list_comparisons` 已輸出 id、`get_comparison` 本來就收 id，**不需要改工具**。純文字「比較 N」維持原行為。
- **卡片內容全部來自 MCP 工具的輸出**，轉接層只負責排版，不查資料庫、不增加欄位、不重算數字（[ADR-0004](0004-llm-never-produces-numbers.md)、[ADR-0033](0033-line-bot-adapter-over-mcp.md)）。卡片想顯示工具輸出沒有的東西（縮圖、方案 logo），先改工具，不繞過去。
- **待辦卡有「到網頁處理」的網址按鈕**，網址用既有的 `PUBLIC_BASE_URL` 組成；LINE 仍然只能查，不能改（[ADR-0034](0034-mcp-write-tools-and-phases.md) 與先前的決定）。
- **圖文選單用一次性管理腳本建立**（`make line-richmenu`），讀選單圖與按鈕設定，建立並設為所有使用者的預設選單；不在每次啟動時自動建立，也不做後台介面。按鈕只放四個：我的比較、理賠待辦、使用說明、開啟網站。**不放「綁定」**，綁定要輸入綁定碼，點一下做不到。
- **版面、顏色與文案先用暫定版**（沿用好險有你的品牌色，文案標註暫定），請設計者確認；選單圖由設計者提供。

## 取捨與沒選的做法

- **只做圖文選單、不做 Flex**：改動最小，但回覆內容仍是一長串文字，列表與詳情不好讀。
- **按鈕用「傳文字」**：實作最簡單，但聊天室會出現使用者沒打的字，而且帶編號的按鈕在列表變動後可能點到錯的筆。
- **Flex 內容自己查資料庫來豐富版面**：卡片可以更漂亮，但繞過 MCP 的驗證、限流與稽核，也讓 LINE 與 AI 助理看到的資料不一致。
- **每次啟動自動建立圖文選單**：免手動，但每次部署都打 LINE API，也難以更換圖片與回溯；一次性腳本更可控。
- **用 LLM 產生卡片文案**：違反 [ADR-0004](0004-llm-never-produces-numbers.md)，也讓 Demo 不可預期。

## 後果

- 轉接層多了 Flex 組裝模組與 postback 處理；LINE 客戶端介面要能送 Flex 訊息（真實與假的兩個實作都要支援）。
- Flex 的呈現在不同手機與 LINE 版本略有差異，需要實機驗證；降級為純文字是安全網。
- 圖文選單的圖片與按鈕設定放在 repo 之外或另開資料夾由設計者交付；選單內容改動不需要部署，重跑腳本即可。
- 純文字指令與快速回覆保留，不使用卡片的情境（例如舊版 LINE）仍然能用。
