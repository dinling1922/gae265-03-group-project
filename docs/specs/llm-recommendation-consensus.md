# 1-3 LLM 推薦：討論共識（2026-11-17 grill）

決策紀錄見 [ADR-0032](../adr/0032-recommendation-by-llm-need-levels.md)；名詞見 GLOSSARY 的「需求等級」「推薦方案」「對照方案」「推薦保額」。

## 流程

1. 使用者在 1-2 按「下一步」（PATCH 比較紀錄）時呼叫 LLM，上限 15 秒，按鈕顯示載入中。
2. **LLM**：讀旅遊日程（含日程活動）與使用者選的在意事項（最多 3 項），替每項判斷**需求等級**（「越高越好」或「有就好」），各附一句點名日程活動的原因。不看方案資料。
3. **程式**：在所有「方案 × 保額」組合中：
   - 先篩「有就好」：達到剩下組合中最高額度的 50%；剩下的組合都沒有這項時略過。
   - 再篩「越高越好」：達到剩下組合中最高額度的 80%。
   - 取保費最低的，得到**推薦方案**與**推薦保額**。
   - **對照方案**：不同方案；在比推薦方案便宜的其他方案中用同一套規則選；推薦方案已最便宜時，在其他所有方案中選。
   - 80%、50% 是可調整的設定。
4. **失敗退回**：LLM 失敗、超時、或原因含金額（日程的天數、日期、時間除外）時，整次改用預設需求等級：第 1 名在意事項「越高越好」、其餘「有就好」；推薦理由用固定句型。現在的 `_rank` 刪除，只剩一套規則。
5. **儲存**：需求等級、原因、推薦來源（`llm` 或預設）、兩組方案與保額。

## 1-3 畫面

- 新增需求等級清單，例如「突然生病就醫：越高越好（第 2 天滑雪）」。
- 推薦理由 = LLM 的原因 + 程式固定句型的結論，不寫金額。
- 推薦依據、方案卡片、比較表照舊由程式產生、含數字（`_basis` 已能顯示「次推薦較高」，不用改）。
- 推薦來源不顯示。

## 重新推薦的時機

- 天數、在意事項或日程活動改變 → 清掉舊推薦，下次 1-2 → 1-3 時重新推薦。
- 改保額不重新推薦。

## 不在這一期

- 條款比對（RAG，第 2 期）。
- 使用者在 1-3 自己改需求等級。
- 推薦集中在少數方案：實作後用範例日程看分布再決定是否調門檻。
