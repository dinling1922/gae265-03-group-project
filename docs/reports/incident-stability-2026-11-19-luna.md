### 條款問答 luna 0/10 的根因（#462）

0/10 的 10 次回覆都是「（無法產生白話說明，以下直接列出條款原文。）」。後端 log 的退回原因是 `問答 agent 失敗：OpenAIInvalidRequestError`，剛好 10 次；不是數字檢查沒過（#439）。

在後端容器裡用最小請求重現：純對話呼叫正常，綁定工具就被 luna 拒絕，HTTP 400：

```text
Error code: 400 - {'error': {'message': "Function tools with reasoning_effort are not supported for this model in /v1/chat/completions. To use function tools, use /v1/responses or set reasoning_effort to 'none'.", 'type': 'invalid_request_error', 'param': 'reasoning_effort', 'code': None}}
```

條款問答用 `create_agent` 帶 `search_rules` 工具，所以 luna 上每一題都會失敗，由備援改成貼條款原文（同 #462 在正式站看到的「幾乎每題都貼原文」）。5 號其他 LLM 呼叫（取出欄位、守門）不帶工具，不受影響。這次量測的待辦檢查本來就沒有檢查條款問答，所以待辦 140/140 看不出來。

### 429 限流

log 有 14 次 `429 Too Many Requests`（約 1,170 次請求的 1.2%），集中在「班機延誤（口語、沒給日期）」與 Demo 事故 B。**這是這次量測用的本機自己部署的 luna（每分鐘 100,000 token）才有的限流**；正式站用團隊的資源，額度不同，不能直接拿這個比例推到正式站。原因是從 log 推論，沒有另外驗證額度。
